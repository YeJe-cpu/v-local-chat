# 数据准备：密钥获取与解密（技术说明）

> 本文只做**技术方法说明**，帮助你在自己的机器、对你自己有权访问的数据完成一次性的环境准备。
> 本仓库不附带开箱即用的抓取脚本。下述方法在多个公开项目中均有记载（见 `NOTICES.md`），非本项目独创。
> 仅限用于你本人拥有并有权访问的数据；请遵守当地法律与平台条款。

## 背景

macOS 微信 4.x 的本地聊天库使用 SQLCipher 加密。要在本地做分析，需要先拿到密钥、把库解密成明文 SQLite。

## 方法概览（公开技术路线）

1. **密钥获取**：微信运行时会调用系统的 `CCKeyDerivationPBKDF`（Apple CommonCrypto 的 PBKDF2）来派生数据库密钥。用 `frida` hook 这个系统函数，即可在派生发生时读到密钥。
   - 需要先移除桌面副本的 Hardened Runtime 签名，`frida` 才能注入。
   - 实践要点：用 spawn 暂停态**预装 hook** 再 resume，避免 hook 装晚了错过密钥派生（早期脚本常见的时序竞态）。
2. **数据库解密**：SQLCipher 4 的标准参数——AES-256-CBC、page size 4096、reserve 80、HMAC-SHA512、PBKDF2 迭代。按这些参数逐页解密即可得到明文 SQLite。

## 已知边界

- **仅 macOS**：本方法针对 macOS 微信；抓取只支持 macOS，需要 `frida`。
- **有时效性**：软件每次大版本更新后，可能需要重新签名桌面副本、甚至方法失效。这是这类技术的固有特性。
- **新库轮转**：消息按 `message_0/1/2…` 分片存储；消息增多或客户端重启时会新建库（如 `message_6`）装新消息，新库有独立密钥。表现为"突然读不到最新消息"——按同样流程再抓一次即可（抓取脚本会自动发现所有库、按盐值匹配，无需手动指定）。这不是密钥失效、也不必然是版本升级。
- **图片**：部分图片是腾讯私有的 wxgf 编码，标准解码器无法解码（本地硬限制）。可解码的 JPEG/PNG 已在面板正常显示。
