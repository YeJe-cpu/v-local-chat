# 第三步：分析时的注意点（防踩坑）

> 这些是我们自己反复踩坑后总结的。把它们喂给大模型当规范，能明显减少"张冠李戴"。

## 说话人与回应关系（最容易错，也最值钱）

大模型读长对话时最爱犯两类错：把发言安错人、把话安错对象。数据里其实已经把确定信息标好了，**以标注为准，别脑补**：

- **说话人**：每条消息都带 `sender`，是从数据库解析出来的事实，不是让你猜的。凡"谁说了什么"一律以该标注为准。
- **引用回复**：被回复的原话在 `reply_to.quoted`、被回复人在 `reply_to.to_name`。判断"谁在回应谁 / 谁夸谁"**只认这个锚点**。
- **@提及**：被 @ 的人在 `mentions`。判断喊话对象以此为准。
- **没有引用/@锚点时**：别因为两条消息相邻就断定是一问一答。群里多人交错刷屏，相邻 ≠ 对话。此时只能写"根据上下文推测"，不能断言。
- **引用原句而非自由复述**：涉及关键结论/归属时，宁可带上"谁 + 原话"引用，也别凭记忆转述——转述最容易串位。
- **两人私聊**：按发言人逐轮交替核对，别把一方的话安到另一方。
- **`群友-xxxxxx`**：非好友群成员没解析出昵称时的稳定标签。同后缀=同一人，不同后缀=不同人；当固定匿名者，别和某个具名的人合并，也别猜他是谁。

## 图片

- **表情**：`[破涕为笑]` 等微信内置表情已归一化成 😂（白名单，绝不误伤营销文案/prompt 模板里的方括号）。
- **wxgf 私有编码**：部分图片是腾讯私有编码，本地**无法解码**（行业硬限制）。实测占比从 2025-08 起出现、且逐月上涨（近月约 20%，只看已下载的图更高）——**"看不了高清"会越来越常见，这是微信机制，不是工具 bug。**
- **高清何时有**：用户在微信里点开看过 → 有高清；只划过 → 本地可能只有 180px 缩略图（微信有时凌晨后台批次才补齐）。

## 朋友圈图片

- 文案能精确到人到条；**图片能解密**（和聊天图片同一套加密），但所有好友的圈图混放在一个大缓存池、命名私有，**无法自动归属"这张是谁的哪条"**。若需要，只能按发圈时间窗解密候选、人工挑。这是已知的墙，非工具缺陷。

## 数据完整性

- `history`/`search` 给了 `--start-time`/`--end-time` 就取全量、不截断；不给时间范围才回退"最近若干条"速览。若"搜不到"，先确认时间范围，别急着下"数据没了"的结论。
