# 分析防踩坑（都是真金白银踩出来的）

> 这些坑我们一个个踩过、也一个个填了。把"分析规范"那节喂给大模型当规则，能明显减少"张冠李戴"；其余是工具/机制层面的坑，帮你少走弯路。

## 一、说话人与回应关系（最容易错，也最值钱）

大模型读长对话时最爱犯两类错：把发言安错人、把话安错对象。数据里其实已经把确定信息标好了，**以标注为准，别脑补**：

- **说话人**：每条消息都带 `sender`，是从数据库解析出来的事实。凡"谁说了什么"一律以该标注为准。
- **引用回复**：被回复的原话在 `reply_to.quoted`、被回复人在 `reply_to.to_name`。判断"谁在回应谁 / 谁夸谁"**只认这个锚点**。
- **@提及**：被 @ 的人在 `mentions`。判断喊话对象以此为准。
- **没有锚点时**：别因为两条消息相邻就断定是一问一答。群里多人交错刷屏，相邻 ≠ 对话。此时只能写"根据上下文推测"，不能断言。
- **引用原句而非自由复述**：涉及关键结论/归属时，宁可带上"谁 + 原话"，也别凭记忆转述——转述最容易串位。
- **两人私聊**：按发言人逐轮交替核对，别把一方的话安到另一方。
- **`群友-xxxxxx`**：非好友群成员没解析出昵称时的稳定标签。同后缀=同一人；当固定匿名者，别和某个具名的人合并，也别猜他是谁。

## 二、我们踩过、已经填好的坑（了解即可，工具已处理）

- **引用会被误标成"链接/文件"**：当你回复的那条消息**本身也是一条引用回复**时，数据库把被引用类型记成 49，真实文本藏在嵌套 XML 的 `<title>` 里。老逻辑直接标成"链接/文件"、把原文丢了。已修：解析嵌套取真实文本。
- **@列表里吐出原始 id / CDATA**：`<atuserlist>` 外面包了 `<![CDATA[...]]>`，里面可能是 wxid、也可能是微信号别名或 `notify@all`。直接吐出来就是一串乱码。已修：剥 CDATA、解析昵称、解不出的一律丢弃。
- **表情白名单不能"不认识就删"**：全库扫出 289 种 `[xxx]`，但大多**不是表情**——`[￥99任洗5件]`(营销)、`[公司名称]`(简历占位)、`[粘贴最近3-5句对话]`(prompt 模板)。所以只能白名单精确匹配，名单外原样保留，否则会啃掉真实正文。
- **数据/呈现别耦合**：早期把回复/@ 折进正文，导致界面被 `[回复 X「…」]` 刷屏。正确做法：提取层只产干净正文 + 结构化字段，呈现由各渲染层自己决定。
- **`--start-time` 会被默认条数截断**：`history`/`search` 老默认只取最近 50 条，带了时间范围也截断（"拉 7/6 却只从 7/11 起"）。已修：给了时间范围就取全量。**"搜不到"时先确认时间范围，别急着下"数据没了"的结论。**
- **AI 说"图片看不了"，八成是漏了导出这步**：图片在本地是**加密缓存**，消息里的 `image_path` 是加密 `.dat`，直接读只有乱码。正确姿势：`python3 engine/vault.py export-media <会话> --out <目录>` 解密成真实 `.jpg`，**再用读图工具读那个 `.jpg`**，画面就看见了。我们自己也栽过：出图能力早就做好了，却因为文档里留着一句"图片内容默认不可见"的旧话，AI 照做直接放弃、全程只看文字。**教训：能力升级后必须回头清掉文档里与新能力矛盾的旧指令，否则做好的能力会被一句话废掉。**
- **`limit` 别截错方向**：`get_chat_history` 现在的语义是——**给了时间范围就取全量**（不给才兜底 2000 条，且截最近的）。早期版本无论如何都截"最老的 N 条"，拉一整月却只看到月初几天，极易被误判成"后面的数据没了"。
- **改了代码没生效？先看是不是旧进程**：启动脚本若没"先杀旧实例"，端口被占时新进程会静默退出，浏览器打开的还是旧代码。本仓库 `启动.command` 已加杀旧实例。
- **系统消息别当人算**：群里"X邀请Y加入了群聊""Y与群里其他人不是朋友关系""群公告"等是**系统消息（local_type 10000）**，不是任何人的发言。**新群里这类消息成百上千**——若按 `real_sender_id` 挂到某人头上、又没在聚合里排除，就会有人**凭入群通知霸榜"发言最多"**。已修：系统消息统一归 `sender="系统"` + `is_system` 标记，聚合/精华按类型排除（不靠内容文字匹配）；带 XML 的系统消息（群公告）显示为"[系统消息]"、不吐原始 XML。

## 三、图片（两套路径 + 硬限制，务必知道）

- **聊天图片 ≠ 朋友圈图片，是两套存储**：都用同一套 V2 加密、同一把密钥可解，但**位置和归属方式不同**。聊天图按会话哈希分目录、能定位到人到消息；朋友圈图全好友混放一个缓存池。
- **色差坑（已填）**：微信图片 AES 加密区实际是 1040 字节（PKCS#7 多补一整块 16 字节），老代码当 1024，导致 JPEG 大面积偏色。修正后颜色正常。
- **wxgf 私有编码 = 本地无解（会越来越多）**：部分图片是腾讯私有的 wxgf 编码，标准解码器全解成绿屏/乱码，是行业硬限制。实测占比：`2023-09 ~ 2025-07` 为 **0%**，`2025-08` 起出现、`2026-07` 约 **20%**（只看已下载的图更高）。归因是软件版本/时间，非设备。**"看不了高清"会越来越常见，这是软件机制、不是工具 bug，请如实告知用户。**
- **高清何时有**：用户在软件里点开看过 → 会触发下载（有时凌晨后台批次才补齐）；只划过 → 本地可能只有 180px 缩略图。**跨设备**：手机点开约 1 分钟后 Mac 也会拿到（前提两端都登录+软件在运行）。
- **🚫 严禁由"只有缩略图"反推"用户没点开过"**（2026-07-22 实测证伪）：用户确实点开了、软件也确实把高清下下来了（磁盘上 277KB 的 `.dat` 就在那），**但那份高清是 wxgf 私有编码、本地解不开**，于是只能退回 12KB 的缩略图。照这条错推断就会对用户说"你没点开过，回头补一下"——**既冤枉人，建议还无效**。
  判断原因**只看导出统计的两个细分计数**，不许自己猜：`thumb_hd_is_wxgf`（高清已下载但私有编码无解 → 点开也没用，别建议去点）、`thumb_hd_missing`（本地确实没有高清文件 → 才可以建议点开后重跑）。
- **缩略图是真图、能正常打开**，只是小（约 180px、十几 KB）。低清能看清的可以描述，**看不清的必须明说"这个分辨率看不清"，不许猜细节写死**。

> **常见追问：为什么某张图拿不到高清 / 只显示缩略图？** 有且只有两种原因，别怀疑工具坏了：
> 1. **你没点开看过**——本地只下了 180px 缩略图。去软件里点开那张图（进全屏），几分钟内高清就会下到本地，重新导出即可。
> 2. **这张图的高清本身是 wxgf 私有编码**——这种**点开也没用**：软件下下来的"高清"就是 wxgf 格式，标准解码器全解成绿屏，本地无法解码（行业硬限制）。判断方法：本地有 `.dat` 但没有可解码的 `_h.dat`。这类图占比随新版软件在上涨（近月约 20%、只看已下载的更高），是软件的编码机制，不是本工具能解决的。

## 四、朋友圈（文案能到人到条，图片归属是墙）

- 文案、发布时间、图片元数据（尺寸/md5/CDN url）都能从 `sns.db` 精确拿到。
- **图片能解密**（和聊天图片同一套加密），但所有好友的圈图混放在一个缓存池、文件名是私有 hash、解密后 md5 与库记录不一致、CDN 直连返回 400——**四条路都试过，无法自动归属"这张是谁的哪条"**。若确需，只能按发圈时间窗解密候选、人工挑。这是已知的墙，非工具缺陷。

## 五、其它

- **视频**是明文 MP4，可直接取；同样受"点开/下载过才有完整文件"影响。
- **文件 / 链接 / 小程序 / 网盘提取码**都在库里，可提取（文件本体受 CDN 过期约 14 天影响）。
- **自动化点界面有风控红线**：连续快速翻图（每秒数张）会触发强制登出（非永久封号，重登恢复，密钥不受影响）。若要自动化补高清，必须放慢到接近人类节奏。手动看图是零风险保底。
