# 第一步：获取密钥（指引，非脚本）

> 本项目**只提供方法指引，不提供开箱即用的抓取脚本**。请在**你本人拥有、且有权访问**的设备与数据上操作，并遵守当地法律与平台条款。
> 这一步是一次性的：拿到一次密钥即可长期复用（除非微信大版本升级）。

## 为什么需要这一步

macOS 微信 4.x 的本地聊天库用 **SQLCipher（AES-256）** 加密。要在本地分析，得先拿到密钥、把库解密成明文。本仓库的面板/引擎读取的是**已解密**的库，所以密钥获取是前置的一次性准备。

## 方法概览（公开技术路线）

微信不把密钥存在磁盘上——它每次开锁时，把一句 passphrase 交给 **macOS 系统自带的密钥派生函数 `CCKeyDerivationPBKDF`**（Apple CommonCrypto 的 PBKDF2）现算现用。突破口正是这里：

1. **复制微信到桌面再操作**（关键，零风险）：对 `Applications` 里的原版微信不做任何改动，只对桌面副本操作，怎么弄都不影响你日常在用的微信。
2. 移除桌面副本的 Hardened Runtime 签名，使 `frida` 可注入。
3. 用 `frida` **hook 系统函数 `CCKeyDerivationPBKDF`**，在密钥被派生出来的那一瞬间读到它。
4. 实践要点：用 spawn 暂停态**预装 hook** 再 resume，避免 hook 装晚了错过密钥派生。
5. 把拿到的密钥保存到本机私有配置（如 `~/.config/wechat-keys.json`）。

拿到密钥后，用第二步的解密脚本把库解成明文即可（见 `engine/decrypt_db.py` 与根目录 README）。

## 边界与风险（务必读）

- **封号风险**：核心操作都在 macOS 本机生态完成，微信服务端监听不到。真正要避免的是**自动化点微信界面/高频操作**——那才可能触发风控。正常准备一次密钥、之后纯本地只读，是安全的。
- **仅 macOS**：抓密钥只支持 macOS 微信，需要 `frida`。
- **有时效性**：微信每次大版本更新可能需要重新准备、甚至方法失效。**当前 `4.1.11.55` 实测可用，但不保证以后。**
- **生态法律风险真实存在**：同类里最火的 PyWxDump 于 2025-10 收到律师函、作者删库下架。请低调自用，勿传播、勿商用。
