# 第一步：获取密钥（指引，非脚本）

> 本项目只提供方法指引，不提供开箱即用的抓取脚本。请在你本人拥有、且有权访问的设备与数据上操作，遵守当地法律与平台条款。
> 这一步基本是一次性的：拿到密钥即可长期复用。但有两种情况需要**再抓一次**（很快、同样的流程）：①软件大版本升级；②软件把新消息**轮转进了一个新数据库**（详见文末"关于新数据库"）。

## 一句话原理

macOS 微信的本地聊天库用 SQLCipher（AES-256）加密。软件不把密钥存磁盘上——它每次开锁时，把一句暗号交给 macOS 系统自带的密钥派生函数 `CCKeyDerivationPBKDF`（Apple CommonCrypto 的 PBKDF2）现算现用。突破口就在这：用 `frida` hook 这个系统函数，在密钥被算出来的那一瞬间读到它。

## 你（人）要做什么 vs. Agent 要做什么

这一步最舒服的方式，是让一个能跑命令行的 AI Agent（Claude Code / Codex / Grok build 等）帮你操作，你只需在几个关键点上配合：

| 步骤 | 谁做 | 具体动作 |
|------|------|---------|
| 1. 复制软件到桌面 | **人**（或 Agent 引导） | 把 `Applications` 里的微信 **`cp -R` 一份到桌面**。⚠️关键：只动副本，绝不动原版，这样你怎么弄都不影响日常在用的那个。 |
| 2. 去掉副本签名 | Agent | 对桌面副本移除 Hardened Runtime 签名（`codesign`），让 `frida` 能注入。**需要你输一次本机密码。** |
| 3. 装 frida | Agent | `pip install frida-tools`（若没装）。 |
| 4. spawn + 预装 hook | Agent | 用 frida **spawn 暂停态启动**桌面副本、**先装好 hook 再 resume**（顺序很重要，装晚了会错过密钥派生）。 |
| 5. 扫码登录 | **人** | 副本弹出后用手机扫码登录——这是唯一必须你亲手做的一步。 |
| 6. 抓到密钥 | Agent | 登录瞬间 hook 捕获到每个库的 32 字节密钥，保存到本机私有配置（如 `~/.config/wechat-keys.json`）。 |

拿到密钥后，回到 README 第二步，用 `engine/decrypt_db.py` 把库解成明文即可。

## 边界与风险（务必读）

- **封号风险 → 不会。** 核心操作都在 macOS 本机生态完成，服务端监听不到。真正要避免的只有：别去自动化点软件界面、别高频操作，那才可能触发风控。
- **不影响原版软件。** 全程只对桌面副本操作，原版签名、登录、截图权限都不受影响。
- **仅 macOS**，需要 `frida`。
- **有时效性。** 软件大版本更新可能需要重新准备、甚至方法失效。当前实测 `4.1.11.55` 与 `4.1.12` 均可用（4.1.12 的加密结构、库格式与 4.1.11 一致，旧钥匙照解），但不保证以后。

## 关于"新数据库"（读不到最新消息时先看这里）

软件不是把聊天存一个大库，而是分片存在多个库里（`message_0.db`、`message_1.db`……）。**随着消息增多、或软件重启，它会新建一个库（如 `message_6.db`）来装新消息。** 新库有自己独立的密钥，而你上次抓的钥匙串里没有它——于是"最新的消息突然读不到了"。

- **这不是密钥失效**（旧库的旧钥匙照样能用），**也不一定是版本升级**（消息攒够了就会轮转）。
- **解决**：把获取密钥的流程**再跑一次**即可。抓取时在登录后的软件副本里多打开几个会话、往上翻翻历史，让它把各个库（含新库）的密钥都派生出来，一次抓全。
- 抓取脚本会自动发现所有库并按数据库盐值匹配保存，不需要你手动指定库名。
- **生态法律风险真实存在。** 同类里最火的 PyWxDump 于 2025-10 收到律师函、作者删库下架。请低调自用，勿传播、勿商用。
