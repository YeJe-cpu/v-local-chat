# v-local-chat

**把你本机的聊天记录，一键重组成一眼能读的日报、精华与素材。** 纯本地运行，不上传、不联网、不接任何第三方 API。

> 面向 macOS 微信（当前版本已验证）。这是一个**本地聊天数据分析面板 + Claude Code Skill**：
> 它不替你做 AI 分析，而是把你**自己拥有**的聊天记录，整理成干净、带关系锚点的结构化文本 / HTML，
> 你再拿去喂给任意大模型（Claude / Codex / 任何 LLM）总结即可。

## 为什么做它

群消息一天几百上千条，翻不完；私聊想留个上下文备份、想复盘一段关系，也没趁手的工具。
市面上的同类多半只支持老版本微信、或把"分析"硬塞进工具里。这个项目只做一件事并把它做好：
**把原始消息，确定性地重组成人和大模型都好读的形态。**

## 亮点（这些是本项目的原创工作）

- **说话人确定性还原**：每条消息的发言人来自数据库事实，不靠大模型猜；非好友群成员的昵称，用"引用回复配对"建**群花名册**反解，连没备注的人也能显示真名。
- **回应关系还原**：引用回复（回复了谁的哪句原话）、@提及（@了谁）都被结构化提取，直接告诉你"谁在回应谁"——大模型最容易在这里张冠李戴，我们把它变成确定信息。
- **表情归一化**：微信内置表情 `[破涕为笑]` → 😂（白名单，绝不误伤营销文案 / prompt 模板里的方括号）。
- **图片色差修复**：微信 macOS 图片 `.dat` 的 AES 分块填充坑（导致 JPEG 大面积色偏）已修正，可解码的图颜色正常、可展示可导出；腾讯私有 wxgf 编码本地无解（硬限制，如实标注）。
- **数据 / 呈现分离**：提取层只产干净正文 + 结构化字段，面板把回复渲染成低调引用行，给大模型的素材另带文本锚点——两种诉求各取所需，界面不乱。

## 三个场景

| 场景 | 输入 | 输出 |
|------|------|------|
| **群聊精华** | 群 + 时间范围 | 按发言人聚合、按贡献度排序，一眼看出谁在输出干货；干货 + 链接列表 |
| **素材提取** | 群/联系人 + 时间范围 | 图文/链接/文件按时间分组，可导出 |
| **信息导出** | 联系人 | 对话时间线 + 上下文备份，导出 Markdown |

## 安装与使用

本面板读取的是**已经解密到本地**的聊天库。密钥获取与解密属一次性环境准备，
其技术方法见 [`docs/key-extraction-technique.md`](docs/key-extraction-technique.md)
（本仓库**不附带**开箱即用的抓取脚本，请按文档在**你本人授权的数据**上自行准备）。

```bash
pip install flask pycryptodome zstandard
python3 panel/server.py        # 浏览器打开 http://127.0.0.1:5678
# 可选：VLC_PORT 换端口，VLC_DECRYPTED_DIR 指定已解密库目录
```

## 常见问题（QA）

**Q：封号风险大吗？**
读取本地已解密的数据库是纯离线只读，不碰微信进程、不发任何网络请求，这部分零风险。真正有风险的是"抓密钥"那一次性动作（需对桌面副本操作），以及任何试图自动化操作微信界面的行为——后者不建议。

**Q：语音消息能转文字吗？**
面板只标出语音消息及其时长占位，不内置转写。你可以把语音文件另行喂给 ASR。

**Q：语音、图片、文字混在一起会乱吗？**
不会。所有类型在同一条时间线上按时间排序，只是类型字段不同，能还原完整对话流。

**Q：引用关系能识别吗？**
能，且是**确定性**识别——引用回复和 @ 都从数据库结构化字段提取，不靠语义猜。没用引用功能的"隔空回应"才需要大模型推断。

**Q：文件 / 链接 / 小程序能提取吗？**
能。文件名、链接、小程序跳转 URL、网盘提取码等元数据都在库里，可提取（文件本体受"是否下载过"影响）。

**Q：图片一定能拿到高清吗？**
取决于你在微信里有没有点开看过：点开过→有高清；只划过→本地可能只有 180px 缩略图（微信有时会在凌晨后台批次补下高清）。这是微信机制，不是工具问题。

## 边界与免责

- **仅 macOS**：抓密钥只支持 macOS 微信，需要 frida。
- **有时效性**：微信每次大版本更新后可能需要重新准备、甚至方法失效。**当前版本可用，但不保证后续升级后依然有效。**
- **wxgf 图片**：部分图片是腾讯私有编码，本地无法解码。
- **仅限授权数据**：只在**你本人拥有、且有权访问**的数据上使用。请遵守当地法律与平台条款。作者不对任何滥用负责。
